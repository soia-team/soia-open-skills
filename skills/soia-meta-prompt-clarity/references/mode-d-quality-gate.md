# 规格化质量与前向验证

这是质量判断，不规定固定格式、评分或每次对抗。规格流程见 mode-d-specification.md；本文件不重复流程。

## 不能接受的结果

- 明确要求消失；把必须改为可选、自动动作改成仅建议、全部对象改成代表样本。
- 虚构模型、价格、路径、工具参数、测试结果、所有权或授权。
- 语言转换把 `must` 弱化成 `should/may`，或增强用户没有给出的义务。
- 双语版本的需求、占位、范围与停止条件不一致。
- 用命名框架替代模式 C 红线、需求对应或验收。
- 只交规格说明却没有完整可用提示词；没有真实阻断项却只返回问题。
- 把安装入口当源码仓，把本地调试安装冒充正式远端验收。
- 新增结构不服务于原要求，或为一般改动另建状态库/治理流程。

发现问题时只修影响范围，再复核相关要求；不因一个局部错误强制全稿重做。

## 真实回归输入

| 输入 | 应验证的行为 |
|---|---|
| 一句润色请求 | 直接给简短结果，不强制模式 D、框架或回执头 |
| 偏长但目标明确的提示词 | 保留有效内容，精简重复，不增系统规格 |
| 所有权/授权不清的正当请求 | 必要事实先澄清，不能编造授权或删除核心目标 |
| 全模型/全推理档不遗漏 | 保留实际范围盘点、完整集合与完成条件，不抽样 |
| 要自动选模型并记录实际模型和费用 | 自动选择、请求/实际区别和每次计量要求不弱化；未知值明确 |
| 只给价格/源码文件路径 | 不声称已知内容，要求执行者读取真实来源 |
| 修改技能并发布、远端安装验收 | 找源码真源，保留授权与发布依赖顺序，不直接改消费入口 |
| 中文说明、英文提示词或完整双语 | 语言分工正确，两版义务与范围等价 |

复杂工程回归可以使用以下原始需求，不预先提供答案：跨宿主工具；完整模型与推理档；另一个执行器同样完整覆盖；读取给定价格来源；成本计算；每次 Token/费用；机器可读事实源；按难度自动选择且显式指定优先。逐项核对，不按文风或黄金文本打分。

## 验证边界

静态检查只证明资源、依赖和规则存在，不证明目标模型能稳定执行。重大方法改动在工具/授权允许时做一次干净上下文前向：只给原请求、技能与必要原料，不给预期答案、诊断或修复方案。

检查实际输出是否保留要求、区分未知并可直接使用。记录模型可验证信息、输入/输出和日期；缺实际模型证据时明确未验证。外部付费调用或机器变更需单独授权。

未做模型前向时只能报告 static_rules_ready / behavioral_validation_pending；一个样本通过也不宣称所有模型等效或全输入有效。无需为每次普通提示词起草启动独立 Agent。
